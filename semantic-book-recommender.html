01 / Overview

Search for a book the way you would describe it to a friend

This project turns a public book dataset into a recommender that understands meaning rather than exact keywords. A reader types a description, the app finds books with similar descriptions, and filters refine the results by category and emotional tone.

02 / Problem

Readers can describe a book long before they can name one

Title and genre search assume a reader already knows what to look for. I wanted to serve the more common situation: someone who knows the mood or theme they are after, but has no title in mind and gets little from a broad category like Fiction.

How might a reader find their next book using only a description of what they feel like reading?

What success looked like

  • A reader can search with a natural-language description instead of keywords.
  • Results can be narrowed by a clean, simple set of categories.
  • Results can also be filtered by emotional tone.
  • Everything is usable through a simple web interface, with no setup for the reader.

03 / Data

Cleaning for search quality kept 5,197 of 6,810 books

I used the 7k Books with Metadata dataset, published on Kaggle by Dylan Castillo. It has 6,810 rows, 12 columns and no duplicate ISBNs. Because semantic search depends on the description text, I treated description quality as the main constraint.

How I cleaned it

  • Removed records missing the ISBN-13, title, description, publication year, rating or page count.
  • Normalized extra spaces and line breaks in descriptions.
  • Kept descriptions of at least 25 words, since shorter ones give embeddings too little context.
  • Combined titles and subtitles into a single display field.
  • Added automated checks for empty output, missing values, short descriptions and duplicate ISBNs.

04 / Approach

Semantic search first, then filters that refine the results

The system has five stages, from raw records to the interface a reader uses.

  1. Clean the records Pandas filters incomplete metadata and short descriptions, producing 5,197 records.
  2. Embed and index Cleaned descriptions become semantic embeddings, indexed in Chroma to support natural-language similarity search.
  3. Assign categories BART-large-MNLI zero-shot classification categorizes 1,454 previously unlabeled books.
  4. Score emotional tone A Hugging Face emotion model scores each description, so results can be filtered by tones such as joyful, suspenseful or sad.
  5. Retrieve and display A Gradio interface retrieves 50 semantic candidates and displays up to 16 recommendations using the category and tone filters.

05 / Key decisions

Three choices that shaped the system

Each of these had a real alternative. Here is what I chose, what I gave up and why.

Minimum description length

Chose
Keep only descriptions of 25 words or more.
Alternative
Keep every book with any description, which would have offered a larger catalog.
Why
Short descriptions do not provide enough context for useful embeddings. A smaller catalog with better matches was the better trade.

Zero-shot classification for missing categories

Chose
BART-large-MNLI, evaluated on 600 labeled descriptions before use.
Alternative
Train a custom classifier, or leave uncategorized books out of filtered results.
Why
It needed no training pipeline and kept unlabeled books discoverable, and the labeled sample let me measure its accuracy first.

Retrieve 50, display up to 16

Chose
Fetch a wider candidate pool, then filter it down for display.
Alternative
Retrieve only the 16 closest matches and apply filters to those.
Why
A strict filter could otherwise leave a reader with only a few results. The larger pool leaves room to filter.

08 / Limits & next steps

What this version does not do yet

Current limitations

  • At 77.83% accuracy, about 22% of the sampled descriptions were misclassified, so some inferred categories will be wrong.
  • The catalog is limited to the 5,197 books that passed cleaning.
  • Recommendation relevance has not been tested with real readers.
  • Results reflect description text only, not reader ratings or reading history.

What I would do next

  • Measure retrieval quality with a hand-labeled query set and precision@k.
  • Combine semantic and keyword search, so exact titles and authors also work well.
  • Use average ratings as a ranking signal.
  • Deploy a public demo and collect feedback from readers.

09 / What I learned

Most of the quality came before the model

  • Data decisions are product decisions. The 25-word rule directly changed which books a reader could discover.
  • Measure before you trust a model. Testing on labeled data first told me how much weight the inferred categories could carry.
  • My frontend background still matters. Thinking about how a reader would use the filters shaped how I designed the pipeline behind them.
